# دکمه بومی Menu تلگرام

تغییر برای همان دکمه کنار کادر پیام است که Telegram با Menu یا آیکون فرمان‌ها نمایش می‌دهد. این قابلیت با ReplyKeyboard زیر پیام و دکمه inline «بازگشت به منو» تفاوت دارد. رنگ و عنوان دقیق دکمه را کلاینت تلگرام تعیین می‌کند؛ ربات نوع Commands و فهرست فرمان‌ها را تنظیم می‌کند.

## رفتار

در startup، post_init پس از initialize تلگرام و پیش از polling، setMyCommands را برای همه گفت‌وگوهای خصوصی در زبان پیش‌فرض و fa ثبت می‌کند. سپس MenuButtonCommands پیش‌فرض فعال می‌شود. برای هر ADMIN_IDS، scope اختصاصی همان chat شامل فرمان‌های عمومی و مدیریتی ثبت و دکمه Commands صریحاً تنظیم می‌شود. برای نمایش Menu لازم نیست به همه کاربران پیام جدید ارسال شود.

کاربر با انتخاب Menu و «شروع و نمایش منوی اصلی» فرمان /start را بدون تایپ انتخاب می‌کند. منوی عمومی شامل حساب، خرید، سفارش‌ها، بررسی ایمیل، تحلیل عمومی اینستاگرام، راهنما، کانال و لغو است. فرمان‌های admin، stats، reply، instagram و channelstats فقط به فهرست اختصاصی ادمین اضافه می‌شوند. همه فرمان‌های فهرست، handler موجود دارند؛ فرمان تازه‌ای که در نسخه قبلی ناشناخته باشد اضافه نشده است.

در /start نیز تنظیم همان chat بررسی می‌شود تا override قدیمی MenuButton یا فهرست فرمان‌ها اصلاح شود. موفقیت هر chat همراه نقش در bot_data همین پردازش cache می‌شود؛ تغییر نقش باعث تنظیم مجدد می‌شود. بعد از Restart، تنظیمات دوباره همگام می‌شوند. اگر ادمینی از config حذف شده، /start بعدی فهرست خصوصی او را عمومی می‌کند. scope منو جای مجوز handler را نمی‌گیرد؛ کنترل ADMIN_IDS در backend حفظ شده است.

خطای Telegram، عدم تأیید API و timeout منو ثبت می‌شود ولی /start یا پردازش اصلی را متوقف نمی‌کند. خطاهای خام دارای کلید/اطلاعات اتصال چاپ نمی‌شوند. تنظیم هر chat حداکثر ۵ ثانیه و مجموعه startup حداکثر ۲۰ ثانیه محدود است. خطا cache نمی‌شود تا در /start بعدی دوباره تلاش شود. هیچ retry سریع یا حلقه همیشگی وجود ندارد.

## نصب محافظت‌شده

هنوز روی سرور نصب نشده است. ابتدا pull شاخه feature در پوشه جدا، سپس فقط Preflight:

```bash
cd /opt/radepa-support-stage/Radepa-Channel-Update/Radepa-server-review
/opt/radepa/venv/bin/python -B tools/install_telegram_menu.py --stage "$PWD"
```

PREFLIGHT_OK و NO_CHANGES باید دیده شوند. ابزار app جدید را به fingerprint ثابت و نسخه فعال را به کد پشتیبانی نصب‌شده 856f07b می‌بندد. requirements و venv باید همان نسخه پایدار باشند. روی baseline ناشناخته یا تغییر سورس توقف می‌کند. در این مرحله هیچ تماس API Telegram، تغییر DB، backup یا توقف سرویس انجام نمی‌شود.

نصب واقعی فقط پس از تأیید جداگانه و توقف موقت مجاز:

```bash
/opt/radepa/venv/bin/python -B tools/install_telegram_menu.py --stage "$PWD" --apply
```

ابزار از engine آزموده‌شده نصب app-only استفاده می‌کند: snapshot و restore-check قبل از stop، probe روی SQLite کپی، refresh backup بعد از stop، حفظ venv/.env/requirements، جایگزینی کامل app و بازگشت کد در شکست. تغییر جدید منو schema تازه ندارد. نیاز به نصب بسته جدید، تغییر BotFather یا انتقال توکن در چت نیست. از installer قدیمی Inspector یا install_support_replies.py برای نصب این app جدید استفاده نکنید؛ guard تاریخی آن‌ها حفظ شده است.

کپی engine بازیابی در BACKUP/tools/install_support_replies.py ذخیره می‌شود. برای rollback مجاز همان --rollback مسیر BACKUP طبق SUPPORT_INSTALL_FA.md استفاده شود. کد قدیمی با همه فرمان‌های ثبت‌شده فعلی سازگار است؛ metadata منو در Telegram نگه‌داری می‌شود و با rollback فایل‌های سرور خودکار پاک نمی‌شود. بازگشت کد قرار نیست ظاهر Menu را حذف کند؛ /start و سایر فرمان‌های موجود همچنان handler دارند. راه‌اندازی نسخه جدید metadata Telegram را با توکن موجود ربات به‌روز می‌کند؛ در تست‌های توسعه این تماس‌ها mock شده‌اند.

## پذیرش روی تلگرام

1. بعد از INSTALL_OK و فعال‌شدن سرویس، گفت‌وگوی ربات را در تلگرام ببندید و دوباره باز کنید تا cache کلاینت تازه شود.
2. کاربر عادی Menu را باز و «شروع و نمایش منوی اصلی» را انتخاب کند؛ منوی اصلی و موجودی باید نمایش داده شوند، بدون تایپ /start.
3. ادمین علاوه بر فرمان‌های عمومی، admin و reply را در فهرست ببیند. کاربر عادی نباید از طریق handlerهای ادمین مجوز بگیرد.
4. اگر قبلاً override اختصاصی برای همان chat تنظیم شده، انتخاب /start یک بار تنظیم chat را همگام می‌کند. کلاینت جدید قبل از اولین شروع، ممکن است دکمه Start تلگرام را نمایش دهد؛ این رفتار طبیعی Telegram است.
5. پشتیبانی، پرداخت و بررسی ایمیل دوباره از منو قابل انتخاب باشند. صرف نمایان‌شدن Menu، موفقیت API پولی یا دسترسی Instagram را اثبات نمی‌کند.

این تغییر، خطای 403 اینستاگرام را رفع نمی‌کند. تا نصب و پذیرش دستی، نمایش واقعی Menu روی حساب‌های کاربران تأیید نشده است. PR merge نشده و در آماده‌سازی این کد هیچ Restart یا تغییر Production انجام نشده است.

## اعتبارسنجی توسعه — ۲۰۲۶-۱۱-۰۴

کل ۱۸۹ تست در Python 3.12 بدون failure/error/skip موفق شدند. در کانتینر تازه Ubuntu 22.04 با Python 3.10.12 و PTB 21.5 نیز ۱۸۹ تست بدون failure/error موفق بودند؛ فقط یک تست نامرتبطِ Chromium سیستم، به علت نبود آن مرورگر در کانتینر، skip شد. pip check، syntax پایتون 3.10، fingerprint منطبق با installer و diff check موفق‌اند. تست‌های تازه، scope عمومی و ادمین، زبان پیش‌فرض/fa، cache نقش، شکست/timeout API، حفظ /start و ثبت واقعی post_init را پوشش می‌دهند. wrapper نصب نیز بدون --apply فقط preflight را فراخوانی می‌کند و با --apply/rollback از قفل engine قبلاً آزموده‌شده استفاده می‌کند.

همه تماس‌های Telegram در تست‌ها mock هستند؛ نمایش روی کلاینت واقعی هنوز پذیرش نشده است. هشدارهای ساختگی Forbidden/Timeout و پیام INSTALL_OK در خروجی unit test به معنی تماس یا نصب واقعی نیستند.
