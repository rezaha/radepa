# نصب محافظت‌شده پاسخ‌گویی پشتیبانی

این ابزار برای ارتقای نصب تأییدشده 38fd00a به کد پشتیبانی 856f07b است. ابزار و تست‌های آن بعد از commit کد پشتیبانی اضافه شده‌اند؛ پس دریافت Git باید شامل همین فایل هم باشد. venv پایدار فعلی، symlink آن، cache مرورگر، .env، requirements و unit سرویس جایگزین نمی‌شوند. PR merge نمی‌شود. تغییر اصلی app است؛ علاوه بر پاسخ‌گویی، اصلاح گزارش 403 موجود در شاخه نیز وارد نسخه نصب‌شده می‌شود. این اصلاح، دسترسی مسدودشده Instagram را رفع نمی‌کند.

## مرحله فقط‌خواندنی

از مسیر دریافت‌شده پروژه، پس از pull:

```bash
cd /opt/radepa-support-stage/Radepa-Channel-Update/Radepa-server-review
/opt/radepa/venv/bin/python -B tools/install_support_replies.py --stage "$PWD"
```

خروجی موفق PREFLIGHT_OK و NO_CHANGES است. این حالت backup، توقف سرویس، migration یا کپی فایل انجام نمی‌دهد. سورس app با fingerprint ثابت، کد فعال با baseline شناخته‌شده، requirements برابر، سرویس root، مسیر و ExecStart، Python پایدار حداقل 3.10، pip check و وجود مسیر واقعی دیتابیس بررسی می‌شوند. تنظیمات محیط سرویس درون پردازش خوانده می‌شوند و مقدار کلیدها چاپ نمی‌شود. وجود PLAYWRIGHT_BROWSERS_PATH فعلی مجاز و مقدار آن حفظ می‌شود؛ installer قدیمی انتشار مرورگر جای این ابزار نیست.

## نصب واقعی؛ فقط پس از تأیید جداگانه

این فرمان باعث توقف موقت و راه‌اندازی ربات می‌شود. در آماده‌سازی این ابزار اجرا نشده است:

```bash
/opt/radepa/venv/bin/python -B tools/install_support_replies.py --stage "$PWD" --apply
```

قبل از توقف، backup کامل app، تنظیمات، requirements، venv، SQLite، اطلاعات unit و فهرست بسته‌ها با هش و integrity/restore-check ساخته می‌شود. مسیر BACKUP را نگه دارید. کپی مستقل app جدید تأیید و import/migration روی کپی SQLite با تنظیمات واقعی و DB_PATH/LOG_FILE آزمایشی بررسی می‌شود؛ polling انجام نمی‌شود.

پس از توقف و تأیید MainPID=0، کد/venv/تنظیمات دوباره از نظر drift بررسی، backup SQLite تازه و migration کپی دوباره آزمایش می‌شوند. app قدیمی در displaced-app نگه داشته و کل app تأییدشده جایگزین می‌شود؛ overlay چندفایلی انجام نمی‌شود. startup معمول ربات جدول‌های افزایشی پشتیبانی را در دیتابیس فعال ایجاد می‌کند. سرویس راه‌اندازی و فعال‌بودن پردازش بررسی می‌شود؛ INSTALL_OK تضمین تحویل واقعی Telegram نیست و پذیرش دستی لازم است.

کل عملیات نصب و rollback با قفل مشترک انتشار محافظت می‌شود. اجرای دوباره همان نسخه، پس از preflight، ALREADY_CURRENT می‌دهد و سرویس را متوقف نمی‌کند. نیاز به نصب وابستگی Python یا سیستم جدید نیست.

## بازگشت

در خطای نصب، ابزار برای بازگرداندن app قبلی و راه‌اندازی آن اقدام می‌کند. venv، تنظیمات و SQLite جاری حفظ می‌شوند؛ اعتبار و پرداخت جدید حذف نمی‌شوند. برای rollback کد، جدول‌های افزایشی پشتیبانی حذف نمی‌شوند. شکست probe اولیه یا snapshot قبل از stop، سرویس را متوقف نمی‌کند.

کپی همان ابزار و release_manager.py کنار backup نگه‌داری می‌شود. برای بازگشت دستی مجاز، با مسیر BACKUP واقعی:

```bash
/opt/radepa/venv/bin/python -B \
  /root/radepa-backups/inspector-BACKUP_ID/tools/install_support_replies.py \
  --rollback /root/radepa-backups/inspector-BACKUP_ID
```

این کار نیز stop/start دارد. ابزار ابتدا نوع backup، کد و محیط فعال را بررسی می‌کند؛ انتشار جدیدتر یا venv تغییرکرده را خودسرانه عقب نمی‌برد. با سرویس خاموش از SQLite فعلی backup تازه می‌گیرد و سپس app قبلی را بازمی‌گرداند. در failure، مسیر backup را نگه دارید و خروجی را بررسی کنید؛ اجرای تکراری بدون بررسی توصیه نمی‌شود.

## پذیرش دستی پس از نصب

با حساب آزمایشی پیام پشتیبانی بدهید و با حساب ادمین پاسخ مستقیم و دکمه پاسخ را امتحان کنید. برای پیام‌های پیش از نصب، /reply با شناسه عددی صریح استفاده شود. کاربر بدون username باید پاسخ بگیرد. پاسخ شبیه ایمیل یا پاسخ تصویری نباید جست‌وجو یا رسید پرداخت شود. خطای blocked باید بدون ادعای موفقیت نمایش داده شود. موجودی، سفارش‌ها و /start را کنترل کنید. اطلاعات کاربران و آرشیو backup را عمومی نکنید.

تست‌های ابزار با SQLite موقت و systemctl شبیه‌سازی‌شده‌اند؛ هیچ فرمان نصب یا rollback Production هنگام توسعه اجرا نشده است. baseline یا source ناشناخته باعث توقف می‌شود و نیازمند بازبینی جداست؛ allowlist را برای عبور از خطا به‌دلخواه تغییر ندهید.

نتایج توسعه در ۲۰۲۶-۱۱-۰۳: ۱۲ تست مخصوص نصب‌کننده و کل suite شامل ۱۷۵ تست بدون failure/error/skip در محیط توسعه Python 3.12 موفق شدند؛ pip check، syntax پایتون 3.10 و diff check نیز موفق‌اند. اجرای واقعی ۱۶۳ تست قابلیت پشتیبانی با یک skip مرورگر سیستم، قبلاً توسط مدیر روی سرور گزارش شده است؛ ۱۲ تست نصب‌کننده بعداً اضافه شده‌اند و موفقیت توسعه آن‌ها به معنی اجرای نصب Production نیست.
