# بازبینی شاخه Inspector

## محدوده

این ماژول فقط دسترسی و ساختار عمومی یک صفحه ثابت را بررسی می‌کند. دستور /instagram ورودی نمی‌گیرد؛ هیچ نام کاربری وارد نمی‌شود، فرم ارسال نمی‌شود، اطلاعات تماس ماسک‌شده استخراج نمی‌شود و گزارش هویت یا مالکیت حساب تولید نمی‌شود. بررسی و اصلاح روی feature/instagram-page-inspector انجام شده؛ Pull Request ادغام نشده و هیچ دستور روی سرور اصلی اجرا نشده است.

## ایرادها و اصلاحات

- شاخه اولیه بر مبنای first uploading بود، نه نسخه فعال توسعه. تغییرات تا 3ea86bb از شاخه codex/single-search-payments-20261026 به شاخه feature وارد شدند تا نصب کامل feature پرداخت تک‌جست‌وجویی، AbstractAPI، نمایش رسید و تاریخچه مدیریت را عقب نبرد. این همگام‌سازی شاخه feature است، نه merge کردن PR به main.
- import مستقیم Playwright در مسیر import app.main باعث می‌شد نبود آن کل ربات را متوقف کند. import به داخل تابع اختیاری منتقل شد و startup بدون Playwright آزمایش شده است.
- اجرای دستور با block=True می‌توانست دریافت سایر پیام‌های پرداخت و ایمیل را تا پایان مرورگر معطل کند. CommandHandler با block=False ثبت شد؛ قفل داخلی همچنان تنها یک بررسی را مجاز می‌کند.
- آزادسازی مرورگر در خطای ناوبری، پاسخ خالی، timeout و لغو بررسی شد. زمان بستن مرورگر محدود شده و متن خطاهای حاوی اطلاعات احتمالی حساس نمایش داده نمی‌شود.
- پراکسی تعریف‌شده محیط به Playwright منتقل می‌شود؛ اطلاعات احراز هویت پراکسی از URL تنظیم server جدا نگه داشته می‌شود. TLS verification غیرفعال نشده است.
- نسخه Playwright به 1.64.1 تثبیت شد. python-telegram-bot همچنان دقیقاً 21.5 است. تست متنی نام username با کنترل امضای بدون ورودی و کنترل AST عملیات فرم جایگزین شد؛ نام کاربری پراکسی، ورودی حساب اینستاگرام نیست.

## شواهد بررسی

آزمون اختصاصی اجرای واقعی Chromium روی HTTP fixture محلی، بدون تماس با اینستاگرام، وجود فیلد و دکمه را بررسی می‌کند. آزمون‌های دیگر نقش ادمین، گفت‌وگوی خصوصی، رد آرگومان، اجرای هم‌زمان، لغو، پاک‌سازی منابع و startup بدون Playwright را پوشش می‌دهند. تست SerpAPI نیز ترکیب خروجی آن و کسر فقط یک اعتبار اینستاگرام را کنترل می‌کند. تست‌های موجود پرداخت، ایمیل، رسید و پنل حفظ شده‌اند.

تست واقعی اینستاگرام اجرا نشده است. دامنه اینستاگرام در policy مجاز همین محیط وجود ندارد. نتیجه محلی تضمین نمی‌کند خود اینستاگرام روی IP سرور صفحه ثابت بدهد؛ redirect، challenge و محدودیت سرویس همچنان ممکن است. خطای دسترسی مجوز عبور از محدودیت یا دور زدن challenge نیست.

امکان خواندن metadata PR با gh در این محیط خطای Forbidden داد؛ شاخه از Git HTTPS واکشی شد. عنوان و شماره PR طبق اعلام کاربر است. هیچ درخواست merge یا تغییری در وضعیت PR انجام نشده است.

## Ubuntu 22.04 و /opt/radepa

ساختار app، app.main، requirements.txt، SQLite و متغیرهای .env با ساختار گزارش‌شده /opt/radepa حفظ شده است. وضعیت لحظه‌ای سورس، دیتابیس، unit سرویس و نسخه Python سرور از این محیط قابل تأیید نیست. Python محلی تست 3.12 است؛ Python گزارش‌شده قبلی سرور 3.11.0rc1 بوده، بنابراین تست staging با مفسر خود سرور لازم است.

فعلاً نصب نکنید. برای آماده‌سازی آتی روی staging مجزا، از Python سازگار استفاده و requirements.txt همین شاخه را در venv جدا نصب کنید. علاوه بر بسته Python، مرورگر و کتابخانه‌های سیستم باید نصب شوند:

```bash
/path/to/stage-venv/bin/python -m pip install -r requirements.txt
/path/to/stage-venv/bin/python -m playwright install --with-deps chromium
/path/to/stage-venv/bin/python -m pip check
PYTHONDONTWRITEBYTECODE=1 /path/to/stage-venv/bin/python -m unittest discover -s tests -v
```

این دستور نصب سیستم در محیط حاضر اجرا نشده و باید در staging Ubuntu بررسی شود. دانلود مرورگر باید با TLS و checksum پیش‌فرض معتبر انجام شود. مرورگر باید برای همان کاربر اجرای سرویس قابل دسترسی باشد؛ مرورگر نصب‌شده در cache کاربر دیگر کافی نیست. PLAYWRIGHT_BROWSERS_PATH در نصب و اجرای سرویس باید سازگار باشد. برای Chromium از قبل نصب‌شده، INSTAGRAM_INSPECT_BROWSER_PATH می‌تواند مسیر اجرایی معتبر را مشخص کند؛ تست محلی با /usr/bin/chromium اجرا شده است.

پیش از انتشار آینده، backup معتبر و تست بازیابی کد، تنظیمات، venv و SQLite لازم است. installerهای قدیمی پروژه به fingerprint و requirements نسخه‌های قبلی وابسته‌اند و برای این شاخه مناسب نیستند؛ با دور زدن guard آنها نصب نکنید. این بازبینی نصب‌کننده production جدیدی اجرا یا منتشر نکرده است.

## نتیجه نهایی اجرای تست‌ها

- کل suite: ۱۱۷ تست، همگی موفق؛ بدون skip در اجرای محلی حاضر.
- Inspector: ۱۵ تست؛ به علاوه یک تست جداگانه رگرسیون SerpAPI.
- مرورگر واقعی: Chromium سیستم روی fixture محلی؛ هیچ نام کاربری یا درخواست بازیابی به اینستاگرام ارسال نشد.
- نسخه‌های نصب‌شده بررسی‌شده: python-telegram-bot==21.5 و playwright==1.64.1.
- pip check: بدون وابستگی ناسازگار. diff check: بدون خطای whitespace با رعایت CRLF فایل‌های قدیمی.
- startup واقعی ساخت Application با run_polling شبیه‌سازی‌شده و Playwright عمداً غایب موفق بود؛ ثبت دستور block=False بررسی شد.
